# RPA Bot สำหรับบันทึกข้อมูลพฤติกรรมเข้าสู่ระบบ RMS

## แบบโปรแกรม .exe (ย้ายไปเครื่องอื่นง่ายที่สุด — ไม่ต้องลง Python)

สร้างครั้งเดียวบนเครื่องพัฒนา (ต้องมี Python และ `pip install -r requirements.txt` แล้ว
ต่ออินเทอร์เน็ตตอน build):

```
python build_exe.py        (หรือดับเบิลคลิก build_exe.bat)
```

ได้โฟลเดอร์ `dist/RMS-Bot/` (และ `dist/RMS-Bot.zip`) — ก็อปไปเครื่องไหนก็ได้ ดับเบิลคลิก
`RMS-Bot.exe` แล้วกรอกบัญชีครั้งแรกในหน้าต่าง (รหัสผ่านเก็บในเครื่องนั้น ไม่ติดไปกับโฟลเดอร์)

- `RMS-Bot.exe` = หน้าต่างควบคุม (เหมือน `control_panel.bat` ทุกอย่าง แต่ไม่ต้องมี Python)
- `rms-bot-runner.exe` = ตัวรันบอท ใช้กับ Task Scheduler ได้ (แทน `run_bot.bat`)
  และใช้ `rms-bot-runner.exe --self-test` ตรวจว่าเครื่องนี้พร้อมใช้ (ไม่ยุ่งกับ RMS/เว็บแอป)
- `config.json` = URL ของเว็บแอป (Apps Script) — deploy ใหม่แล้วได้ URL ใหม่ **แก้ไฟล์นี้ด้วย
  Notepad ได้เลย ไม่ต้อง build ใหม่** (ลำดับความสำคัญ: ตัวแปร `RMS_BOT_GAS_URL` > config.json
  > ค่า `DEFAULT_GAS_API_URL` ใน `sheets_queue.py`) ต้องตรงกับ `src/services/api.js` เสมอ
- `browsers/` = Chromium ที่ฝังมา (ห้ามลบ) และ `logs/bot.log` = บันทึกการทำงานย้อนหลัง

โปรแกรมยังไม่ได้ลงลายเซ็นดิจิทัล Windows SmartScreen อาจเตือน: กด More info > Run anyway

## ใช้งานแบบง่ายที่สุดจากซอร์สโค้ด (สำหรับคนไม่ถนัดเขียนโปรแกรม)

ดับเบิลคลิก **`control_panel.bat`** — จะเปิดหน้าต่างโปรแกรมขึ้นมา (ไม่ใช่จอดำ)
มี 2 ส่วนในหน้าต่างเดียว:

1. **ตั้งค่าบัญชี** — กรอกช่องแล้วกด "บันทึกการตั้งค่า" (ทำครั้งเดียว กรอกเฉพาะ
   ช่องที่ต้องการเปลี่ยน ช่องที่เว้นว่างจะไม่ถูกลบค่าเดิม) รหัสผ่านยังเก็บอย่าง
   ปลอดภัยใน Windows Credential Manager เหมือนเดิมทุกอย่าง แค่เปลี่ยนหน้าตอนกรอก
2. **รันบอท** — กดปุ่ม "ทดสอบ (ไม่บันทึกจริง)" หรือ "รันจริง" แล้วดูผลลัพธ์สดๆ
   ในกล่องข้อความด้านล่างได้เลย ไม่ต้องเปิด PowerShell หรือรอดูจอดำอีกต่อไป

ถ้าอยากตั้งให้บอทรันเองอัตโนมัติทั้งวันโดยไม่ต้องมีคนกดเลย ให้ดูหัวข้อ
"ตั้งให้รันอัตโนมัติเต็มรูปแบบด้วย Windows Task Scheduler" ด้านล่าง (จุดนั้นให้
Task Scheduler เรียก `run_bot.bat` ตรงๆ ไม่ผ่านหน้าต่างนี้ เพราะหน้าต่างโปรแกรม
ต้องมีคนอยู่หน้าจอถึงจะกดปุ่มได้)

## ใช้งานแบบเดิม (ยังใช้ได้อยู่ ถ้าคุ้นเคยกับแบบนี้อยู่แล้ว)

หลังตั้งค่าครั้งแรกเสร็จ (ดูหัวข้อ "ตั้งค่าครั้งแรก" ด้านล่าง) การใช้งานประจำวันมีแค่นี้:

- **ทดสอบ**: ดับเบิลคลิก `run_bot_dryrun.bat`
- **รันจริง**: ดับเบิลคลิก `run_bot.bat`

ไม่ต้องเปิด PowerShell พิมพ์ `$env:...` อีกเลย เพราะรหัสผ่านทั้งหมดเก็บไว้ใน Windows
Credential Manager ที่ตั้งครั้งเดียวจบ โปรแกรมจะอ่านเองอัตโนมัติทุกครั้งที่รัน

## ภาพรวมการทำงาน

```
ครูกรอกฟอร์ม (React) -> GAS -> ชีต "Records" (RMS_Sync_Status = "pending")
                                          |
              ดับเบิลคลิก run_bot.bat (หรือ Task Scheduler รันให้อัตโนมัติ)
                                          |
         บอท login เข้าเว็บแอป EDMS (อ่านรหัสผ่านจาก Windows Credential Manager) -> ได้ token
                                          |
              ดึงคิว -> ทีละรายการ: login RMS -> ค้นหา -> เช็ก REF tag ซ้ำ
                        -> กรอกฟอร์ม -> บันทึก -> อัปเดตสถานะ + log ทันที
                                          |
        สถานะใน Records: synced / needs_review / error
        ประวัติทุกครั้งที่รัน: ชีต "RPA_Log" (สร้างอัตโนมัติ) — ดูได้ว่าสำเร็จ/
        พลาดตอนไหน ใช้เวลาเท่าไหร่ต่อรายการ (ข้อมูลนี้ใช้ในบทที่ 4 ของงานวิจัยได้เลย)
```

## การป้องกันข้อมูลซ้ำ

ทุกรายการที่บอทบันทึกจะฝัง `[REF:<uuid>]` ต่อท้ายช่อง "รายละเอียด" ใน RMS เสมอ
ก่อนบันทึกทุกครั้งบอทจะค้นหา REF tag นี้ในตาราง "พฤติกรรม" ของนักเรียนคนนั้นก่อน
— ถ้าเจอแปลว่าเคยบันทึกไปแล้ว จะข้ามทันที ไม่บันทึกซ้ำ

นอกจากนี้บอทจะสร้างไฟล์ `.bot.lock` ไว้ระหว่างทำงาน กันไม่ให้ Windows Task
Scheduler เผลอสั่งรันอีก instance ซ้อนขึ้นมาระหว่างที่ตัวแรกยังทำงานไม่เสร็จ
(เช่น คิวค้างเยอะจนรันไม่ทันในรอบถัดไปที่ตั้งเวลาไว้) — เช็คจาก PID จริงผ่าน
`tasklist` ไม่ใช่แค่เดาจากเวลา ถ้าโปรเซสเดิม crash ไปโดยไม่ทันลบไฟล์ รอบถัดไปจะ
ตรวจพบเองว่าโปรเซสนั้นตายไปแล้วและรันต่อได้ตามปกติ ไม่ต้องลบไฟล์เองด้วยมือ

## ประสิทธิภาพ — login RMS ครั้งเดียวต่อการรัน 1 รอบ

บอทจะเข้าสู่ระบบ RMS แค่ครั้งเดียวตอนเริ่มรัน แล้วใช้ browser/session เดียวกัน
ประมวลผลทุกรายการในคิว (ไม่ได้เปิด browser + login ใหม่ทุกรายการ) เร็วกว่ามาก
เวลาคิวยาว และไม่เสี่ยงโดนระบบความปลอดภัยของ RMS มองว่า login ถี่ผิดปกติจาก
บัญชีเดียวกัน — ถ้าเซสชันหมดอายุกลางทาง (คิวยาวมากจนเกินอายุ session ของ RMS
เอง) บอทจะตรวจพบเองและเข้าสู่ระบบใหม่อัตโนมัติก่อนไปต่อ

## การแจ้งเตือนเมื่อบอทมีปัญหา

บอทรันแบบไม่มีคนเฝ้า (ผ่าน Task Scheduler) ถ้า login RMS ไม่สำเร็จตั้งแต่ต้น
หรือทุกรายการในคิวพังหมดในรอบเดียว (สัญญาณว่าอาจมีปัญหาระบบ ไม่ใช่แค่รายการ
เดียว) บอทจะส่งข้อความไปให้เว็บแอป EDMS แจ้งเตือนผู้ดูแลระบบทางอีเมลให้อัตโนมัติ
(ใช้ช่องทางเดียวกับที่เว็บใช้แจ้งเตือน error ของตัวเองอยู่แล้ว — ต้องตั้งค่า
`CONFIG.ADMIN_ALERT_EMAIL` ใน `Config.gs` ฝั่ง GAS ไว้ก่อนถึงจะได้รับอีเมล)

## ตั้งค่าครั้งแรก (ทำครั้งเดียว)

```bash
pip install -r requirements.txt
playwright install chromium
```

### 1. อัปเดต Google Apps Script
วางเนื้อหาทุกไฟล์ในโฟลเดอร์ `gas-backend-COMPLETE-v3/` (ทั้ง 11 ไฟล์) ทับของเดิมใน Apps Script
Editor แล้วรัน `setupSyncColumns()` หนึ่งครั้ง จากนั้น **Deploy -> Manage
deployments -> ไอคอนดินสอ -> เปลี่ยน Version เป็น "New version" -> Deploy**

### 2. ตั้งค่าบัญชีบอท
ดับเบิลคลิก `control_panel.bat` แล้วกรอกช่องในหัวข้อ "1. ตั้งค่าบัญชี" ให้ครบ 4
ช่อง (ชื่อผู้ใช้งาน/รหัสผ่านเว็บแอป EDMS และของ RMS จริง) แล้วกด "บันทึกการตั้งค่า"
— รหัสผ่านจะถูกเก็บอย่างปลอดภัยไว้ใน Windows Credential Manager (เข้ารหัสโดย
Windows เอง) ไม่ใช่ไฟล์ข้อความธรรมดา ไม่ต้องแก้ไฟล์ `.env` หรือตั้ง environment
variable ใดๆ เองอีกเลย (ไฟล์ตัวอย่าง `.env.example` เดิมเลิกใช้และถูกลบออกจากโปรเจกต์แล้ว)

### 3. สร้างบัญชีบอท 2 บัญชี (คนละระบบกัน)
- ในเว็บแอป EDMS: login ด้วยบัญชี Admin -> "จัดการผู้ใช้งาน" -> เพิ่มบัญชี `rpa-bot`
- ใน RMS จริง: ขอผู้ดูแลระบบสร้างบัญชีเฉพาะสำหรับบอท (ไม่ใช้บัญชีคนจริง)

### 4. ยืนยันข้อความฐานความผิดที่เหลือใน RMS
เปิด `offense_mapping.py` แก้ `match_text` ของรายการที่ `confidence` ยังเป็น
`"NEEDS_CONFIRM"` (ปัจจุบันเหลือ 2 หมวด: บุหรี่ไฟฟ้า/กัญชา และ "อื่นๆ" — ดู
คอมเมนต์ในแต่ละหมวดว่าทำไมยังไม่ชัด) ให้ตรงกับข้อความจริงที่พิมพ์ไว้ใน RMS แล้ว
เปลี่ยนเป็น `"HIGH"` ถ้าตรวจสอบแล้วว่าตรง

## ตั้งให้รันอัตโนมัติเต็มรูปแบบด้วย Windows Task Scheduler

1. Task Scheduler -> Create Basic Task -> ตั้งความถี่ (เช่น ทุก 15 นาที)
2. Action: Start a program
   - Program: path ของ `run_bot.bat` (ตั้งให้รันไฟล์ .bat ได้เลย ไม่ต้องเรียก
     python.exe ตรงๆ เพราะรหัสผ่านถูกเก็บไว้ใน Windows Credential Manager แล้ว
     ตั้งแต่ตอนตั้งค่าบัญชีผ่าน `control_panel.bat`)
3. **ไม่ต้องตั้ง environment variable ระดับ System อีกแล้ว** — บัญชีที่ตั้งค่าไว้
   ผ่านหน้าต่างควบคุมจะใช้ได้ทันทีทุกครั้งที่ Task Scheduler สั่งรัน ไม่ต้องทำอะไร
   เพิ่มเติมเลย
